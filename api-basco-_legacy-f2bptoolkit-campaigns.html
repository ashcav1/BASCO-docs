basco._legacy.f2bptoolkit.campaigns

Legacy compatibility reference. Prefer current BASCO workflows; copied implementation details are not new development targets.

Observing campaigns: what is measured, how often, and how well.

A campaign is deliberately separated from the dynamics and from the parameter choice. Cases must differ only in what they estimate, never in how much data they were handed -- otherwise a case that looks better may simply have been given a longer arc.

Measurement model

Astrometry of a resolved binary: each observation supplies the relative position vector and, optionally, the orientation of either body.

The attitude partial deserves a note, because it is the one place the 30-state's redundancy shows through. The state carries all nine entries of a DCM, but an attitude measurement constrains only three degrees of freedom. For a perturbation dC the corresponding rotation vector is

dtheta = vee(dC C^T)

since dC = [dtheta]x C is the left (frame) perturbation. vee takes the antisymmetric part, so the six symmetric components of dC -- the off-manifold directions that stretch or shear the DCM -- are correctly given ZERO measurement sensitivity. Using a naive dC -> observable map instead would silently pretend those six directions are observed, and the resulting covariance would be optimistic in exactly the directions that are not physical.

ObservingCampaign.n_measurements

n_measurements(self) -> int

The number of epochs run_case actually stacks.

floor(duration/cadence), NOT round(...)+1: the estimation loop runs for k in range(1, n_use), so the t=0 epoch is never a measurement and a clamped final grid point is never reached. An earlier version returned round(...)+1, which overcounted by one on the named campaigns (2881 reported, 2880 used) and by two for non-divisible cadences.
