basco._legacy.f2bptoolkit.coefficients

Legacy compatibility reference. Prefer current BASCO workflows; copied implementation details are not new development targets.

Post-run conversion: inertia-integral covariance -> gravity-coefficient sigmas.

The estimator works in mass-normalised inertia integrals That^lmn because that is the honest dynamical parameterisation (the polar moments derive from them). Missions and the literature quote spherical-harmonic coefficients C_lm. The two are linearly related, so a CaseResult's covariance maps exactly onto coefficient sigmas -- correlations included -- with no re-run.

Conventions (chosen to match the JPL SSD small-body gravity products, e.g. the OSIRIS-REx Bennu field):

  • Exterior potential U = (GM/r) Sum (R/r)^l P_lm(sin phi) [C_lm cos m lam + ...], with body-fixed axes assumed principal and origin at the centre of mass -- the same assumption the OREx product states, and exactly what our truth bodies satisfy (odd moments and products of inertia vanish).

  • Unnormalised C_lm from the mass-normalised integrals That (units m^2 at degree 2, m^4 at degree 4), reference radius R in metres:

    C20 = (2That002 - That200 - That020) / (2 R^2) # < 0 for oblate C22 = (That200 - That020) / (4 R^2) C40 = [3(That400+That040) + 6That220 + 8That004 - 24(That202+That022)] / (8 R^4) C42 = [6*(That202-That022) - (That400-That040)] / (24 R^4) C44 = [That400 - 6*That220 + That040] / (192 R^4)

Degree-3 and all odd-m terms vanish identically for our centred, principal- axis ellipsoids and are not estimated, so they are not reported. tests/test_coefficients.py verifies every one of these expansions against brute-force Monte Carlo integration of the defining integral on a random triaxial ellipsoid -- the formulas are checked, not trusted.

  • Normalised coefficients Cbar_lm = C_lm / N_lm with N_lm = sqrt( (2 - delta_m0) (2l+1) (l-m)! / (l+m)! ), the geodesy convention the JPL files use (verified: Bennu Jbar2 * sqrt(5) reproduces the published unnormalised J2).

Which coefficients a given run can report

A coefficient is only reportable when the estimated parameter set actually spans its integral combination. Case 5/6 span everything at degree 2; case 2 estimates the SUM T_AB^002, so neither body's C20 is separable there (only C22B is) -- the converter detects this from the Parameter definitions and reports only what is genuinely determined, rather than silently conditioning on the unestimated split.

extend_weights

extend_weights(max_degree: int=12) -> None

Extend _WEIGHTS/_DEG_OF beyond the hand-derived degree-4 table.

Each solid harmonic r^l P_lm(sin phi){cos,sin}(m lambda), times the unnormalised prefactor (2-delta_m0)(l-m)!/(l+m)!, is a homogeneous polynomial of degree l in x, y, z; its monomial weights are recovered by exact least squares on random points (4x oversampled). The geodesy convention has no Condon-Shortley phase, so scipy's lpmv is stripped of its (-1)^m. Every hand-derived row of the static table is reproduced and asserted to 1e-9 before any new row is installed, so degrees 5 and up inherit a verified convention.

coefficient_sigmas

coefficient_sigmas(result, system, case, bodies: Tuple[str, ...]=('A', 'B'), ref_radius_m: Optional[Dict[str, float]]=None)

Map a CaseResult's covariance to gravity-coefficient values and sigmas.

Returns a list of dicts: body, name (e.g. 'C22'), value, sigma (both unnormalised), value_bar, sigma_bar (normalised), frac (= sigma/|value|), ref_radius_m. Only coefficients whose integral combination is exactly spanned by the estimated set are returned.

Right after the degree-2 pair of each body comes one more entry, named 'Izz': the polar moment T200 + T020, which completes C20 and C22 (three numbers for the three estimated second moments). For it "value" is Izz/M in m^2 and "value_bar" is Izz/(M R^2), dimensionless -- the unit the tables use -- with sigma and sigma_bar to match. It has no Kaula prior.
