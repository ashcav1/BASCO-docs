basco._legacy.f2bptoolkit.jacobian

Legacy compatibility reference. Prefer current BASCO workflows; copied implementation details are not new development targets.

Analytic Jacobian of the F2BP equations of motion.

Builds A = dF/dx, the 30x30 Jacobian of the state derivative, from the analytic potential derivatives in the C++ core. This is what makes the variational equations analytic rather than differenced.

State layout, all in the primary's rotating A frame, DCMs stored row-major::

x = [ r(3), v(3), wc(3), ws(3), Cc(9), C(9) ]

Equations of motion, unperturbed, mirroring hou_ode term for term::

rd  = r x wc + v
vd  = v x wc - (1/m) gU
wcd = Ic^-1 [ (Ic wc) x wc + Ma ]
wsd = Isc [ Lb x wc + Mb - (Cd Is C^T + C Is Cd^T) ws ]
Ccd = Cc [wc]x
Cd  = C [C^T ws]x - [wc]x C

with gU = dU/dr, Ma = r x gU - Mb, Mb = -sum_k col_k(C) x grad_k U, Lb = C Is C^T ws, Isc = C Is^-1 C^T.

How the derivatives are organised

Every block is an exact product rule, but written as a directional derivative along each basis direction rather than as an index-summed tensor expression. For a perturbation dC = e_p e_q^T the chain rule through a product of matrices is just the same product with one factor replaced at a time, which is mechanical and very hard to get wrong -- whereas the equivalent explicit index expression involves several Levi-Civita contractions that are easy to transpose. The result is identical; only the bookkeeping differs.

What is differentiated, and why it matters

The CODED form is differentiated, never an algebraically tidier equivalent. C [C^T ws]x equals [ws]x C only when C C^T = I, and RK-integrated C is not exactly orthonormal: GUBAS reprojects nowhere, and the nine entries of C are unconstrained state variables. The two forms agree numerically to the drift, but their JACOBIANS differ, because the admissible perturbations include off-manifold dC. Simplifying would give an A that is wrong in precisely the directions the state transition matrix exists to track. The same applies to Isc = C Is^-1 C^T standing in for the inverse of C Is C^T.

PotentialDerivatives

PotentialDerivatives(order, G, TA_flat, TB_flat)

Analytic derivatives of the mutual potential at one configuration.

Assembles what the Jacobian needs::

gU[i]      = dU/dr_i
H[i,j]     = d2U/dr_i dr_j
W[a,b]     = dU/dC(a,b)
P[i,a,b]   = d2U/dr_i dC(a,b)
Q[a,b,c,d] = d2U/dC(a,b) dC(c,d)

All attitude dependence of U passes through TBp = M(C) TB and the kernel is linear in that slot, so W, P and Q need no new kernel -- only the same kernel evaluated with a differentiated cube substituted.

_basis_cube

_basis_cube(order, lmn)

Unit cube for one slot: 1.0 at (l, m, n), zero everywhere else.

The bound check is not defensive clutter. The flat index is l + m*dim + n*dim^2, which WRAPS silently when any single index exceeds order: at order 4, slot (5,0,0) lands on index 5, which is slot (0,1,0). The parameter would then be reported with a finite, healthy-looking sigma belonging to a completely different moment -- the worst kind of failure, since nothing anywhere would look wrong. It matters now because the degree-3/4 work generates slot lists programmatically rather than listing them by hand.

Note the admissibility rule here is PER-INDEX (each of l, m, n <= order), while _flatten_cube in covariance.py checks TOTAL degree (l+m+n <= order). Those are genuinely different rules feeding the same kernel -- (2,2,2) at order 4 is accepted here and rejected there -- and both are correct for their own job: this one bounds what can be WRITTEN into the cube, that one bounds what the potential can READ out of it. If they are ever merged, keep the stricter.
