basco._legacy.f2bptoolkit.cases

Legacy compatibility reference. Prefer current BASCO workflows; copied implementation details are not new development targets.

Estimation cases: which mass parameters are solved for, and how well.

from basco._legacy.f2bptoolkit.cases import run_case, CASES
from basco._legacy.f2bptoolkit.systems import SYSTEMS
from basco._legacy.f2bptoolkit.campaigns import DART_ASTROMETRY

r = run_case(SYSTEMS["Didymos-postDART"], CASES["case2"], DART_ASTROMETRY)
print(r)

Parameters are named LINEAR COMBINATIONS of inertia integrals, not individual slots. That is not generality for its own sake -- two of the parameters the planar study estimates are combinations:

  • T_AB^002 = T_hat_A^002 + T_hat_B^002, because the planar problem depends on those two only through their sum. Estimating them separately is rank deficient, which is what Case 5 exists to demonstrate.
  • mu = G(M_A + M_B), a scaling of BOTH bodies' full integral sets at fixed normalised shape -- not a perturbation of T^000 alone, since holding the normalised shape fixed while changing the mass necessarily scales every mass-weighted integral with it.

Expressing both in one mechanism means a degree-4 parameter, or any other combination someone later wants, needs no new code -- only a new :class:Parameter. See DEGREE4_EXTRA.

Units

Reported sigmas are on MASS-NORMALISED integrals, T_hat = T/M, matching the planar MATLAB study so the numbers line up directly. GUBAS carries mass-weighted integrals internally; the conversion dx/dT_hat = Psi * M is applied here and is verified in tests/test_case2_degeneracy.py to 5e-15.

tangent_basis

tangent_basis(x)

Map the 18 PHYSICAL degrees of freedom to 30-state perturbations.

The 30-state stores each DCM as nine numbers for three real degrees of freedom, so twelve of its thirty directions are not physical -- they stretch or shear a rotation matrix into something that is no longer one.

Co-estimating all thirty asks the data to determine those twelve fictitious quantities. They are unobservable, so marginalising them out bleeds genuine parameter information into the null space and the parameter sigmas inflate by orders of magnitude. Restricting to the tangent space is not an optimisation; it is what makes the co-estimated problem well posed.

Physical attitude perturbations are dC = [dtheta]x C, three per DCM. Returns a (30, 18) basis whose columns are those directions.

_barycenter_dnu

_barycenter_dnu(case, MA, MB)

d nu / d p in run_case's column coordinates, nu = M_B / (M_A + M_B).

A mass column (scale_body) is d/d eps with dT = eps T for that body, so dM = eps M and

dnu/deps_A = -M_A M_B / M^2 = -nu (1 - nu)
dnu/deps_B = +M_A M_B / M^2 = +nu (1 - nu)

i.e. dnu/dGM_A = -GM_B / GM^2 and dnu/dGM_B = +GM_A / GM^2, times the column scale GM_A or GM_B. mu (scale_all) scales both masses together and leaves nu alone. A shape parameter is a NORMALISED integral, moved at fixed mass, so it leaves nu alone too. A parameter naming a (b, 0, 0, 0) slot directly would move a mass outside these rules and is refused rather than guessed.

run_case

run_case(system, case: Case, campaign, orbits: Optional[float]=None, dt: Optional[float]=None, verbose: bool=False, estimate_state: bool=True, state_prior: Optional[Sequence[float]]=None, check_invariance: bool=True, integrals: Optional[Dict[str, Dict[Tuple[int, int, int], float]]]=None, param_prior: Optional[Sequence[float]]=None, return_channels: bool=False, estimator: str='batch', column_scaling: bool=False, rank_rtol: Optional[float]=None, epoch: str='start', return_cond_history: bool=False, coefficient_prior: Optional[Dict[Tuple[str, str], float]]=None) -> CaseResult

Estimate a case's parameters and return their covariance.

estimator selects how the triangular factor is built: "batch" (one Householder QR of the whole whitened stack, the default and the behaviour of every result before campaign v2) or "srif" (the same factor accumulated SEQUENTIALLY, one measurement epoch at a time, the Tapley/Schutz/Born measurement update). The two agree to rounding; the sequential path additionally records cond(R11) after every epoch when return_cond_history is set, attached as result.cond_history -- the diagnostic that shows WHERE along the arc the state block turns ill conditioned. column_scaling equilibrates the stacked columns to unit norm before factorising and undoes the scaling exactly afterwards: the exact-arithmetic answer is unchanged, the computed digits on a wide-spectrum problem are not. epoch="mid" re-references the co-estimated state to the measurement nearest the arc midpoint by an exact 18 x 18 change of coordinates (prior rows transformed with it, reported state sigmas mapped back to the arc start), which halves the span the state transition matrix must bridge in each direction -- the honest lever against the exponential conditioning growth of a tumbling arc. All three options apply to the estimate_state path; a parameters-only run ignores them.

coefficient_prior (Kaula campaign, 2026-08) is a dict {(body, name): sigma_bar} of ABSOLUTE 4-pi-normalised sigmas on physical gravity coefficients (e.g. ("A", "C31"): 2.4e-3). Each entry becomes one whitened prior row on the parameter block, the gradient of that normalised coefficient with respect to the estimated parameters in column coordinates divided by sigma_bar, about the reference (uniform-density) value. Off by default: None adds no rows and changes nothing. A prior on a coefficient the estimated set does not span raises. Parameters whose truth is exactly zero (an ellipsoid's odd moments) cannot use the fractional column scaling; with a prior given they are scaled by their degree's prior sigma in integral units instead, and without one they raise -- never a silent zero column. The column scale is attached to the result as column_scale so coefficient sigmas can be read back in absolute units whatever the truth.

return_channels=True additionally attaches, as result.channels, the UN-whitened joint (state, parameter) design rows of each measurement channel separately::

{"position_rows": Hp, "attitude_rows": Ha, "nx": 18, "labels": [...]}

Whiten by 1/sigma_p and 1/sigma_a, stack, QR: that is the estimate at ANY noise pair, exactly, without re-propagating -- because Lambda = Hp'Hp/sigma_p^2 + Ha'Ha/sigma_a^2. Rows are kept rather than their Gram matrices so the downstream QR keeps its conditioning advantage. Position rows in km, attitude rows in rad. Off by default; nothing else about the run changes.

A campaign with observe_barycenter (campaigns.py) adds, at every epoch, the primary's barycentric position y = R0 + V0 t - nu Cc r. Its rows are [-nu Hpos Phi B | nuisance | -nu Hpos S + G], where G = -rho dnu/dp is the EXPLICIT mass partial (_barycenter_dnu). The nuisance columns (Legendre in time, spanning R0 + V0 t and optionally a constant acceleration) sit between the physical state and the parameters, are marginalised with the state and are never reported: state_sigma stays the 18 physical DOF. With channels on, nx becomes 18 + n_nuisance, the position and attitude rows carry zero nuisance columns, and barycentric_rows (un-whitened, km) is added, so a sweep in sigma_barycenter needs one propagation. Off by default; with it off nothing changes, bit for bit.

The arc comes from the campaign, not from orbits; orbits is only a cap for quick exploratory runs.

estimate_state (default True) CO-ESTIMATES the initial state alongside the mass parameters, then marginalises it out by Schur complement --

Lambda = sum H0' Rinv H0,   H0 = [ Hy Phi , Hy Psi ]
Lambda_T = Lambda_pp - Lambda_px pinv(Lambda_xx) Lambda_xp

which is what the data say about the integrals after the initial state has been solved for alongside them. This is the honest posture: the initial state is never known exactly, and holding it fixed credits the estimate with information nobody has. It can only ever make the parameter sigmas LARGER.

The pseudo-inverse on the state block is safe and is not the pseudo-inverse trap warned about elsewhere. A state direction that is unobservable has Hy Phi v = 0, so it contributes nothing to Lambda_xp either -- the singular directions do not couple to the parameters, and projecting them out changes nothing. The trap is inverting the PARAMETER block that way, which would report a small variance along an undetermined direction; that is still refused.

Set False to hold the initial state perfectly known -- useful for isolating where information comes from, but optimistic as a result.

integrals (default None) supplies an explicit truth cube per body, mass-weighted SI, replacing the ellipsoid closed form -- the route by which a polyhedral truth model reaches the estimator. The trajectory's initial condition still comes from system.build() (the ellipsoid separation solve), so a cube that differs from the ellipsoid's is propagated from a state slightly off its own equilibrium; for a covariance study that is a feature, not a defect -- real systems are never at equilibrium either.

run_case.column

column(param, Psi_k)

dx / d(this parameter), in normalised units.

For a multi-term parameter theta = sum_j c_j That_j the gradient needs a stated convention for how the individual integrals move when theta moves; the minimum-norm split dThat_j = c_j dtheta / |c|^2 is used, hence the division by sum(c^2). For T_AB^002 in plane this is not a convention at all: dx/dThat_A == dx/dThat_B there, so the division is exactly what makes the column equal dx/d(sum). Without it each slot was perturbed by the FULL dtheta, the column was |c|^2 = 2x the true sensitivity, and the published T_AB^002 sigmas were a factor 2 optimistic in every case that estimated it (2026-08 audit).

run_case._factorize

_factorize(H, want_history=False)

Triangular factor of H, honouring estimator and column_scaling. Column scaling equilibrates before the factorisation and is undone EXACTLY afterwards (H = Q Rs S^-1 with S the scaling, so Rs S^-1 is the unscaled factor and stays triangular): same answer in exact arithmetic, better-computed digits on a wide-spectrum stack. The sequential path feeds the factor one measurement epoch at a time (Tapley/Schutz/Born measurement update) and can record cond(R11) after every epoch.
