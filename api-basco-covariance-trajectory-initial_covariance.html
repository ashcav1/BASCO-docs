basco.covariance.trajectory.initial_covariance

The covariance that is propagated along a particle's trajectory.

InitialCovariance is the covariance of the uncertain inputs q (see the package docstring): the binary's initial state deviation and parameters, plus the particle's own initial position and velocity. It comes from a covariance analysis (from_result) or from numbers you supply (from_covariance, from_factor), and the particle's own uncertainty is added with with_independent_particle or with_independent_release.

It is stored as a factor F with covariance P = F F^T. Mapping F and squaring at the end, (J F)(J F)^T, is more accurate than J P J^T when correlated terms nearly cancel.

InitialCovariance

Import as basco.covariance.trajectory.InitialCovariance

InitialCovariance(layout: ParameterLayout, factor: object, source: str, reference_epoch_s: float, information_cutoff_s: float, diagnostics: dict, _delegate: object = field(repr=False), _appended_factor: object = field(repr=False), _appended_conventions: dict = field(repr=False))

Covariance-only input distribution. Use from_factor for declared physical factors, from_covariance for new supplied PSD matrices, and from_result for existing BASCO solves so their original factors and null-support policy remain intact. Independent inertial or body-fixed release errors can be appended explicitly. Supply a complete joint factor with a release descriptor when binary/release errors are correlated.

The covariance of the uncertain inputs q, as a factor.

layout: the names, units and scales of q. factor: F, with one row per entry of q and P = F F^T, in physical units. source: where the covariance comes from, as text. reference_epoch_s: the time q refers to. information_cutoff_s: the time of the last observation that went into the covariance. diagnostics: details for the records.

Make one with from_result (a CovarianceResult or ConsiderResult), from_covariance or from_factor. Then add the particle's own initial uncertainty:

with_independent_particle(covariance)           inertial position and velocity
with_independent_release(release, covariance)   body-fixed position and velocity

Both assume the particle's error is independent of the binary's. For a correlated one, give the complete joint covariance to from_covariance.

InitialCovariance.with_independent_release

with_independent_release(self, release, covariance=None, *, factor=None, release_epoch_s, scales=None, source='independent body-fixed release uncertainty')

Append six body-fixed COM-offset/relative-velocity errors independent of the original source. The recorded release body, nominal geometry, units and release_epoch_s must agree with the initialization. Original reference/cutoff epochs, factors, consider cancellation and null policy remain intact. Input independence does not remove correlations induced by the uncertain body-to-inertial release map.

Add the particle's initial body-fixed position and velocity (a BodyFixedInitialState) as six more uncertain inputs, independent of the others, at release_epoch_s.

The errors themselves are independent of the binary's. The particle's inertial state is still correlated with the binary, because the body it starts from is.

InitialCovariance.map_factor

map_factor(self, jacobian)

Map a physical Jacobian into original latent errors. Supplied sources use J@F; result-backed sources require their explicit map_factor capability. Independent release/inertial factors retain trailing latent columns. Full-source Jacobians still determine null availability; no factor reconstruction, new information or extra latent rank is introduced by mapping.

Map supported finite directions in the original latent column order.

jacobian is a finite two-dimensional map using every physical source column. Result-backed sources delegate to their original factor-mapping capability, retaining cancellation-aware consider algebra. Independent appended errors retain their own trailing latent columns.

This is a supported-subspace factor, not an availability test. A finite returned row does not imply finite covariance for an unobservable output; use derived_from_factor to apply the original result's null-support policy. Missing result capabilities fail rather than reconstructing dense factors.
