basco.dynamics.variational_equations

The variational equations of the binary: the nominal trajectory with its state transition matrix and its parameter sensitivities.

solution = AnalyticVariationalEquations().propagate(model, parameters, times, RK4(60.0))

solution.epochs[k]                             t_k [s]; epoch 0 is the initial time
solution.gubas_states[k]                       the GUBAS state x(t_k)               (30,)
solution.state_transition[k]                   Phi = dx(t_k) / dx(0)                (30, 30)
solution.inertia_integral_sensitivities[k]     dx(t_k) / d(inertia integrals)       (30, i)
solution.parameter_sensitivities[k]            Psi = dx(t_k) / d(parameters)        (30, p)

The last array is the one before it times d T / d parameter (ParameterSet.inertia_integral_jacobian): the chain rule from inertia integrals to the estimated parameters.

This file holds the analytic version, in which the partials A = dF/dx and B = dF/dT are the hand-derived ones of the GUBAS code kept in basco/_legacy. basco/dynamics/ad holds the automatic-differentiation version, which is the default. Both integrate with integration.py and both return a VariationalSolution.

The functions named legacy_... are the only places that call the legacy code.

Immutable epochs, native30 states, state transition, raw SI-moment sensitivities, physical-coordinate sensitivities, diagnostics and validity identity. Save labels/units and identity with numerical arrays; raw and physical sensitivity axes are different.

The result of integrating the variational equations (see the top of this file).

inertia_integral_indices: the (body, l, m, n) of the columns of inertia_integral_sensitivities. diagnostics: timings, settings and checks of the integration. fingerprint: a record of the inputs that produced this solution. A solution is reused for another analysis only when that analysis has the same fingerprint. gubas_labels: names of the 30 entries of the GUBAS state.

integrate_variational_equations

integrate_variational_equations(model, parameters, schedule, integrator, *, provider_name=ANALYTIC_PROVIDER_NAME, prepared=True)

Integrate the variational equations with the hand-derived (analytic) partials.

prepared=True evaluates the partials through AnalyticPartials and integrates with integration.py. prepared=False is the original legacy route, kept for comparison: it integrates the sensitivities and the states in two separate runs of the legacy code.

The legacy partials are per kg km^degree; the factor gubas_inertia_integral_scale converts them to per kg m^degree.
